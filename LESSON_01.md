# Урок 1 — «Экспедиция: Тропа Дерсу» — учебная заготовка

Результат занятия: WASD / стрелки → Input Actions → PlayerInput → OnMove → Rigidbody2D → камера → сбор
трёх предметов → счётчик `0/3`, `1/3`, `2/3`, `3/3` на Canvas.
После третьего предмета игрок продолжает исследование. Финальной зоны и экрана
победы в текущем уроке нет. Показ сообщения о победе — домашнее задание.

## План на 90 минут

- 00–10: Git и клиент Fork, клонирование, ветка от Lesson1_Start.
- 10–25: окна Unity, GameObject, компоненты, локальные и мировые координаты, Prefab.
- 25–55: базовый C#, векторы, Input Actions / PlayerInput, PlayerMovement.
- 55–75: камера и Trigger; Singleton, List и foreach в готовом менеджере.
- 75–90: самостоятельный плейтест, Git, вопросы и домашнее задание.

Про HashSet достаточно объяснить: один и тот же экземпляр предмета считается
один раз, Add возвращает false при повторном добавлении. Разные предметы с
одинаковыми названиями остаются разными находками. Внутреннее устройство и
хэш-функции в этот урок не входят.

## Как объяснить ввод

1. Input Actions — описание действий игрока. Move возвращает Vector2.
2. Bindings связывают Move с устройствами. У нас уже настроены WASD и стрелки
   в Assets/InputSystem_Actions.inputactions, карта Player.
3. PlayerInput включает карту и передаёт события компонентам персонажа.
4. Behavior = Invoke Unity Events. После создания скрипта назначьте в
   Events → Player → Move метод PlayerMovement.OnMove из раздела
   Dynamic InputAction.CallbackContext.
5. OnMove получает context.ReadValue<Vector2>() и запоминает направление.
   При отпускании клавиш canceled даёт нулевое значение.
6. FixedUpdate нормализует сохранённое направление и задаёт linearVelocity.
   Обработчик ввода не двигает Transform и не вызывается как Update каждый кадр.

Фазы started, performed и canceled — этапы одного действия. В этом уроке
достаточно читать Vector2; не нужно ограничивать обработчик только performed,
иначе отмена действия не сбросит сохранённое направление.

## Подключение к сцене

Окружение, размещение предметов и оформление UI собирает преподаватель.

1. Создать `PlayerMovement.cs` с классом `PlayerMovement` в пространстве
   имён `ProjectSchool2026`, написать код движения и добавить компонент
   на корневой объект `Player`. `Rigidbody2D` уже есть на этом объекте.
   Body Type — Dynamic, Gravity Scale — 0, Freeze Rotation Z — включено,
   Interpolate — Interpolate. Поле Rigidbody можно назначить вручную: если оно
   пустое, `Awake` получит компонент через `GetComponent`.
2. Существующий `BoxCollider2D` на дочернем `Player/Visual` можно сохранить.
   Он относится к Rigidbody2D родителя. Is Trigger у игрока выключен.
3. На `Player` настроен `PlayerInput`: Actions — `InputSystem_Actions`,
   Default Map — `Player`, Default Control Scheme — `Keyboard&Mouse`,
   Behavior — `Invoke Unity Events`. Событие Move пока не имеет обработчика:
   после написания скрипта назначить `PlayerMovement.OnMove`.
4. На `Main Camera` добавить `CameraFollow`, в Target назначить корневой
   `Player`. Offset — `(0, 0, -10)`.
5. На `ExplorationManager` список `Required Artifacts` содержит три компонента
   `ArtifactItem` из сцены. Размер списка задаёт общее количество предметов.
   Ссылки должны быть непустыми и не повторяться. После добавления четвёртого
   предмета добавить его в этот список.
6. На Canvas создать текст `TextMeshPro - Text (UI)`, добавить к нему
   `ArtifactCounterView`. В поле Counter View менеджера назначить этот компонент.
   Скрипт показывает только прогресс: подпись и оформление выбирает преподаватель.
   Если Unity запросит TMP Essential Resources, импортировать их.
7. На каждом предмете Collider2D с Is Trigger и `ArtifactItem`.
   Artifact Name — название предмета. Rigidbody2D на самих
   предметах не нужен: он уже есть у игрока.
8. У физических препятствий Collider2D имеет выключенный Is Trigger.

Предмет распознаёт игрока через `other.attachedRigidbody`: это сохраняет
существующую структуру `Player → Visual`, где коллайдер находится на дочернем
объекте. Предмет обращается к `ExplorationManager.Instance`. Singleton означает
один активный менеджер текущей сцены; между сценами он не переносится.

`List<ArtifactItem>` — список целей в Inspector. `HashSet<ArtifactItem>` —
собранные экземпляры без повторов. `CollectArtifact(item)` возвращает true,
только если предмет есть в целях и добавлен впервые; после этого предмет
выключается. `AreAllArtifactsCollected()` через foreach проверяет каждую цель.
После последней находки UI показывает полный прогресс; игра продолжается.
Пустой список не считается завершённой экспедицией.

## Проверка финального варианта

- Сразу после запуска счётчик показывает `0/3`.
- WASD и стрелки двигают игрока; диагональная скорость равна прямой.
- Игрок останавливается при отпускании клавиш и упирается в препятствия.
- Камера следует за Player, сохраняя Z = -10.
- Касание предмета скрывает его и увеличивает прогресс ровно на один.
- Посторонний Collider2D не собирает предмет.
- Все три предмета дают `3/3`; движение остаётся доступным.
- Повторная передача одного предмета менеджеру не увеличивает счётчик.
- Предмет вне Required Artifacts не засчитывается и не исчезает.
- Повторный запуск сцены возвращает предметы и `0/3`.
- Console не содержит ошибок компиляции, Missing Script и исключений.

## Что подготовлено в Lesson1_Start

Сцена, окружение, три предмета, физические компоненты, Input Actions,
PlayerInput и Canvas уже настроены преподавателем. Ссылки камеры, менеджера
и счётчика сохранены; обработчик события Move студенты подключат на занятии.
`ExplorationManager` и `ArtifactCounterView` готовы: их не нужно писать заново.

- `PlayerMovement`: скрипта и его компонента в сцене нет. Студенты создают
  скрипт с нуля: поля скорости, Rigidbody2D и направления, методы `Awake`,
  `OnMove`, `FixedUpdate` и сброс движения в `OnDisable`. Затем добавляют
  компонент на Player и подключают OnMove к событию PlayerInput.
- `CameraFollow`: поля уже есть; студенты заполняют `LateUpdate`.
- `ArtifactItem`: название и свойство уже есть; студенты заполняют
  `OnTriggerEnter2D`. Разобрать поиск Player на Rigidbody2D родителя,
  вызов менеджера и выключение успешно собранного предмета.
- В готовом менеджере разобрать Instance, List, Add и проверку foreach;
  особенности HashSet объяснить кратко.

В начале работы счётчик показывает `0/3`, персонаж не движется, камера
не следует за ним, предметы не собираются. Это ожидаемое поведение заготовки:
оно изменится после заполнения учебных методов.

Студенты создают собственную ветку от `Lesson1_Start` и работают в ней на
занятии и при выполнении домашнего задания. `Lesson1_Final` содержит готовый
результат занятия. В каждой из этих двух веток один начальный коммит.

В конспекте второго преподавателя финальная ветка называется Lesson1_End.
В этом проекте её роль выполняет согласованная `Lesson1_Final`.

Домашнее задание: добавить четвёртый предмет, оформить его как Prefab,
подключить Trigger и ArtifactItem, добавить его в Required Artifacts.
Ожидаемый итоговый прогресс — `4/4`. Затем добавить на Canvas скрытый текст
«Все артефакты собраны!» и показывать его, когда AreAllArtifactsCollected()
возвращает true. В начале новой игры этот текст должен быть скрыт.

## Зависимости

Unity `6000.6.0f1`, Input System `1.20.0`, URP `17.6.0`, uGUI / TextMeshPro
`2.6.0`. `Packages/manifest.json` и `Packages/packages-lock.json` должны храниться
в Git. После изменения manifest Unity должна завершить разрешение пакетов и
обновить lock-файл перед коммитом.
